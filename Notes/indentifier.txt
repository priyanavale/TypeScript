## 2. Why can't a variable name start with a number?

TypeScript follows JavaScript's rules for identifiers.

An identifier is the name used to identify a variable, function, class, or other program element.

For example, these are valid identifiers:

let name = "Alex";
let names123 = "Alex";
let _names = "Alex";
let $names = "Alex";
let firstName = "Alex";
let name123 = "Alex";

But these are invalid:

let 123names = "Alex";
let 1name = "Alex";
let 9age = 25;
let 2026year = "Current year";

The important distinction is:

- `names123` is valid because it starts with a letter.
- `_names` is valid because it starts with an underscore.
- `$names` is valid because it starts with a dollar sign.
- `123names` is invalid because it starts with a digit.

### What is the rule?

In ordinary TypeScript identifiers, the first character can be a letter, an underscore (`_`), a dollar sign (`$`), or certain Unicode identifier characters. A digit can appear after the first character, but it cannot be the first character.

For example:

| Identifier | Valid? | Reason |
| --- | --- | --- |
| `name` | Yes | Starts with a letter |
| `Name` | Yes | Starts with a letter |
| `_name` | Yes | Starts with `_` |
| `$name` | Yes | Starts with `$` |
| `name123` | Yes | Digits appear after the first character |
| `123name` | No | Starts with a digit |
| `1name` | No | Starts with a digit |
| `name_123` | Yes | Starts with a letter |

One detail: identifiers are case-sensitive, so `name`, `Name`, and `NAME` are three different names.

### Error 1: An identifier or keyword cannot immediately follow a numeric literal

What does the error mean in simple English?

> "I recognized `123` as a number, but another identifier or keyword immediately follows it. I cannot interpret this combination as valid syntax."

### Error 2: `'string' only refers to a type, but is being used as a value here`

To understand the distinction, consider the following:

In this declaration:

- `string` is a TypeScript type.
- `"Alex"` is a runtime string value.

TypeScript types describe the kinds of values a program uses. Type annotations such as `: string` are removed when TypeScript is compiled to JavaScript.

For example:

The emitted JavaScript is conceptually:

There is no runtime variable or value called `string` created by the type annotation.

What does this error mean in simple English?

In your original declaration, this is likely a secondary error caused by the invalid variable name and the resulting parser confusion. It does not mean that `string` is wrong in a normal type annotation.

### Error 3: `';' expected.`

What does this error mean in simple English?

## 5. What if you really want the name `"123names"`?

There is an important distinction between a variable name and a string containing a name.

You cannot write:
let 123names: string = "Alex";

But you can use a string as an object property name:

  "123names": "Alex"
};

console.log(person["123names"]);

Output:
Alex

Why does this work?

In this example:

- `person` is a valid variable identifier.
- `"123names"` is a string used as an object property key.
- `person["123names"]` accesses the property by its string key.

Object property names written as strings can contain characters that ordinary variable identifiers cannot.

You can also write:

const person: { "123names": string } = {
  "123names": "Alex"
};

console.log(person["123names"]);

This is valid TypeScript because `"123names"` is being used as a property name, not as a variable identifier.

Notice that this syntax:

person["123names"]

is different from:

123names

The first is a property access using a string key. The second is an invalid attempt to write an identifier starting with a digit.

## 6. Why doesn't TypeScript automatically understand `123names` as one name?

You might wonder why the compiler cannot simply treat the entire sequence as a variable name.

The reason is that the language has rules for recognizing different kinds of tokens, including:

- Identifiers, such as `names` and `age`.
- Numeric literals, such as `123` and `45.6`.
- Keywords, such as `let`, `const`, and `class`.
- Punctuation and operators, such as `:`, `=`, `+`, and `;`.

The sequence `123names` does not match the normal rules for an identifier because an identifier cannot begin with a digit.

The compiler cannot simply assume that you intended to create a variable named `123names`, because that would conflict with how numeric literals are recognized in the language.

Instead, the code must follow the language's syntax rules.
